# 摄像头启动、黑屏诊断与例程模式

2026-11-10，基于 `b39cb87` 修订。对照逐飞 `E8_14_mt9v03x_ips200_display_demo`，保留当前双核架构与IPS200驱动，修复已复现的命令覆盖和信标标记问题，增加采集/显示诊断。本机未执行烧录；用户在后续操作中反馈Image已有画面，但没有单独记录当时的模式与读数，信标识别及行驶尚未完成实车验收。

## 使用顺序

1. 停车，进入主菜单 **Image**。摄像头处于OFF或初始化失败时会请求CPU1启动；已经READY时不重复初始化。也可继续使用 **Params → Beacon → Camera On**。
2. 初始化失败时，Image页会显示失败提示，**确认键重试，返回键退出**。正常显示时，确认键循环 `BIN+L → BIN → GRAY`，上下键改变曝光。
3. 要按逐飞例程的配置排查，停车进入 **Params → Camera → Diag 50/512**。它重新初始化摄像头，配置50 FPS、曝光512，并采用原始图像诊断路径。返回Image，切到GRAY查看。
4. 完成诊断后，停车进入 **Params → Camera → Normal Camera**。它重新初始化摄像头，恢复驱动默认配置帧率（当前100）与正常RAM曝光参数，再恢复循迹/信标处理。

50/100是请求配置，实际采集/处理帧率以F和计数变化为准。例程诊断不运行循迹或信标算法，不提供有效Run目标，不能在该状态发起视觉跑车。Balance等现有直立控制路径保持原样；相机模式切换动作只接受停车状态。

诊断模式的上下键曝光修改不写正常 `g_param.cam_exposure`。诊断模式选择不加入Flash参数表；整板复位恢复正常模式，正常曝光仍按现有Flash加载规则处理。摄像头初始化仍沿用逐飞驱动的传感器配置流程。

## Image页读数

| 显示 | 含义 |
|---|---|
| BIN+L / BIN / GRAY | 二值叠线／二值／原始灰度 |
| E | 当前请求曝光；正常模式来自RAM参数，诊断模式独立调整 |
| A | 最后一次收到匹配曝光应答的值；0表示本次初始化后尚未确认 |
| EXP:OK / ERR / WAIT / QUEUE / -- | 曝光应答成功／失败／待执行／待交接／未知；不代表光学亮度已经正确 |
| T / V | 本次绘制快照的阈值与识别有效性，原始诊断的V为0 |
| F | CPU0统计到的视觉结果帧率，不是LCD刷新率 |
| P | 原循迹IPM有效性；信标和原始诊断不以它判定图像是否正常 |
| NORMAL100 / RAW50 | 正常处理／原始诊断及请求配置帧率 |
| RAW | CPU1已复制并统计的采集帧序号 |
| LCD | 最近一次已交给LCD驱动绘制的快照帧序号，不是屏幕硬件回读 |
| GRAY min / avg / max | RAW对应稳定灰度帧的最小值、整数均值和最大值，未经过二值化 |
| VS / DM / DROP | 场同步、DMA完整帧、旧帧未消费而跳过采集的累计次数；每次相机重启清零 |

图像约10Hz刷新，LCD序号落后RAW若干帧通常正常；应检查是否长时间完全不变。顶部RAW和LCD不是要求每次相等的计数。

底部提示：

- `WAIT CAMERA FRAME`：尚无采集帧，或视觉结果已超时。
- `WAIT DISPLAY SNAPSHOT`：没有当前显示模式的快照，或显示长时间未更新。
- `CAPTURE PIXELS ALL ZERO`：最近采集灰度帧全部为0。
- `CAPTURE VERY DARK / CHECK EXP`：采集帧最大灰度不超过8，可能非常暗。
- `SNAPSHOT DRAWN / CHECK IMAGE`：像素已交给驱动；仍需观察真实屏幕。
- `COMMAND QUEUE FULL / RETRY`：诊断曝光请求未入队，不会默默覆盖其他命令。

## 软件变化与复查结论

1. **命令交接**：单槽信箱改成8项单生产者/单消费者队列。CPU0前台生产，CPU1消费；写满明确失败，启动、标定、诊断曝光彼此不覆盖，计数支持uint32回绕。调用方不得从CPU0中断并发生产。
2. **曝光恢复**：CPU1先读取参数、执行命令和处理曝光，再等待新帧。正常曝光跟随最新5ms参数快照，合并快速编辑；诊断曝光使用队列。检查设置返回值，失败保留最后确认值，新请求可重试，不每帧重复等待超时。
3. **初始化**：OFF和FAILED都能手动启动；进入Image不额外发送曝光命令。相机重新配置前暂停原VSYNC和DMA并清理采集状态。启动失败不显示曝光成功。
4. **快照所有权**：保留request/read/release协议，增加相机代次；CPU0拒绝重启前遗留的快照。相机重启清除信标追踪历史，避免沿用旧目标。待重配或诊断状态不允许视觉Run启动。
5. **标记范围**：信标快照带来源模式，BIN+L对信标扫描整幅叠加范围；循迹继续使用原有效前瞻范围。
6. **内存**：复用原有图像缓冲，新增小型状态结构、队列和显示计数，没有新增整帧副本，没有缩小栈/堆预留。

原始灰度路径仍是：相机缓冲 → `image_grab()`稳定副本 → `vision_display_publish()`快照 → `display_track_view()` → 原逐飞`ips200_show_gray_image()`。主机测试验证非黑图像在这条路径中没有被清黑，包括信标处理前后、显示模式切换和重启后的旧帧剔除；该测试不模拟真实SPI电气信号或传感器。
